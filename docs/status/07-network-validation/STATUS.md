# 计划 7：网络扰动验证与方案对比

状态：未开始（验收目标已细化，尚无执行结果）。最后更新：2026-10-16。

## 目标

分两阶段验证：先在 Windows 本地服务端与同 Wi-Fi 实际设备上证明公共网络的生命周期、资源边界和交付策略能承受扰动，再使用相同玩法、输入与网络条件对比状态同步和帧同步。所有结论来自实际运行；本轮不验证公网部署或 Linux。

## 当前进度

已在 [公共网络层实施计划](../03-shared-simulation/NETWORK_PLAN.md) N4 中定义初始网络样本、故障场景和观测项。尚未建立网络扰动工具、负载记录或方案对比结果。

## 依赖与边界

- 公共网络验证可从计划 3 的 N1 开始，无须等待两种同步方案全部实现；作为阶段验收持续执行。
- 完整方案对比依赖计划 5、6 各有可运行版本，帧同步同时要求计划 4 的确定性验证。
- 相同机器、构建版本、玩家数、输入记录、游戏 Tick 与网络样本下比较；网络流量和策略参数不同应单独注明，避免把不同传输配置的差异误判为同步算法差异。
- 扰动工具、方向、分布、随机种子和实际 RTT 必须记录。应用消息级模拟与真实网络包级丢失影响不同，不能混为同一结果。

## 任务拆解

- [ ] 选择可重复的延迟、抖动、突发丢包、乱序和重复包模拟方式
- [ ] 按网络计划 N4 运行基线、常见/较差环境、短暂中断和超过失活阈值的中断
- [ ] 验证可靠交付边界、不可靠过期淘汰、跨通道顺序和大消息带宽竞争
- [ ] 验证队列满、超大/畸形 Protobuf 消息、未完成握手的连接超限、版本不符及服务端退出
- [ ] 双客户端至少运行 60 分钟，并验证连接/消息上限，记录资源回收和队列峰值
- [ ] Windows 服务端与同 Wi-Fi 至少两台实际客户端设备验证连通、房间流程、断开 Wi-Fi、暂停恢复及重新加入；记录防火墙/AP 隔离配置
- [ ] 状态同步记录快照率、输入确认延迟、预测误差、校正次数和状态收敛
- [ ] 帧同步记录组帧等待、缺帧/补帧、回滚次数/深度、逻辑哈希及回放结果
- [ ] 共同记录 Tick 耗时、输入到显示的响应、流量、RTT/波动、内存、分配与断线原因
- [ ] 保存复现步骤和参数，区分支持的恢复行为与明确不支持的无缝重连

## 验收方式

公共部分按 N3/N4 验收，预算阈值在执行前确定，未达到的指标保持未完成。方案对比说明观察窗口、样本量、构建及参数，并在同 Wi-Fi 真实设备上分别完成对局，保存失败记录；不以同机进程、一次无报错或单张 HUD 截图代替跨设备验收。公网安全、Linux 和未测平台不在本轮结论内。
